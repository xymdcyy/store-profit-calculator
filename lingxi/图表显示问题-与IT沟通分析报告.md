# 灵犀平台「对话智能体图表无法显示」问题分析报告

> 用途：与平台/IT 技术沟通，定位图表渲染被拦截的根因并给出可选解决路径。
> 应用：TCL 门店盈利测算智能体（chatflow，code 节点内生成图表）
> 日期：2026-09-07

---

## 一、背景

智能体在 code 节点（Python3）计算门店盈利后，需要把「阶梯边际贡献图」「量本利 CVP 图」等图表展示给用户。图表由 code 节点**纯本地代码生成**（不依赖任何插件），随 answer 节点一起输出。

先后试过两种承载方式，均在**前端渲染环节**被拦截，无法稳定显示。

---

## 二、现象与证据

### 方式一：内联 SVG（`<svg>...</svg>` 直接嵌入 markdown）

- **表现**：图表只剩文字残留，图形元素（柱子/折线/圆点）全部消失。
- **证据**（用户页面实际输出）：
  ```
  阶梯边际贡献（瀑布） / 净固定费 33,800 / 智屏-P 智屏-X 智屏-C 智屏-S
  量本利分析（CVP） / 保本点 977,455 / — 收入 / — 总成本
  ```
  这些正是 `<svg>` 内部 `<text>` 标签的文字，而 `<rect>`/`<polyline>`/`<circle>` 等**图形标签从没被渲染出来过**。平台更新后，连文字也被一并剥除，变为空白。

### 方式二：PNG data URI 内嵌图片（`<img src="data:image/png;base64,...">`）

- **表现**：图片位置返回 `[Image blocked: ...]`，图片无法显示。
- **证据**（用户页面实际输出）：
  ```
  阶梯边际贡献（瀑布）
  [Image blocked: 阶梯边际贡献瀑布图]
  量本利分析（CVP）
  [Image blocked: 量本利分析（CVP）图]
  ```

---

## 三、排查与结论

### 3.1 `[Image blocked]` 说明 `<img>` 标签被正常解析，是图片「源」被拦

关键证据：`[Image blocked: 阶梯边际贡献瀑布图]` 里，前端的提示完整带出了 `<img alt="阶梯边际贡献瀑布图">` 的 **alt 文本**。

这说明：
- `<img>` 标签本身**被 markdown 渲染器正常识别、解析**；
- 被拦截的是 **`data:` 开头的图片源地址**，而非"转义问题"。

> 如果存在「转义」问题，页面上应显示 `<img src="data:image/png;base64,...">` 这一长串字面文本，而不是 `[Image blocked]`。因此可以排除"数据带转义"的猜测。

### 3.2 根因判断

前端 markdown 渲染层存在两道安全策略，分别拦掉了两种承载方式：

| 承载方式 | 被拦机制 | 分析 |
|---|---|---|
| 内联 `<svg>` | HTML sanitize（XSS 白名单过滤） | `<rect>`/`<polyline>`/`<circle>` 等非基础标签被剥除，仅保留 `<text>` 等被放行的文字 |
| `<img>` + `data:image/png` | CSP（内容安全策略） | `img-src` 未放行 `data:` 协议，导致 data URI 图片被前端标记为 blocked |

**两种方式都撞在"前端安全策略"上，与图表代码质量、LLM 生成格式无关。**

---

## 四、需要 IT 协助确认/放行的点

以下按"改动成本从低到高"列出，任一方案落地都可恢复真图形渲染。当前代码已同时保留 PNG 与 SVG 两套生成逻辑，确认后**一行即可切换**。

### **方案 A（推荐）：放行 `data:image/png` 图片源**

- **操作**：在前端 markdown 渲染模块的 CSP 中，将 `img-src` 增加 `data:`（或更精确地 `data:image/png`）。
- **改动量**：最小（一个 CSP 配置项）。
- **效果**：`<img src="data:image/png;base64,...">` 即可正常显示，数字图表恢复。
- **风险**：低。`data:image/png` 无脚本执行能力，仅用于展示静态图片；如需更收敛可只对图片格式做限制。

### 方案 B：放行内联 SVG（明确 SVG 白名单）

- **操作**：在 sanitize 白名单中放行 `<svg>` 及其子元素（`rect`/`line`/`polyline`/`circle`/`text`）。
- **改动量**：中等（需配置 sanitize 白名单，且要注意 `<svg>` 可执行脚本，安全面比 PNG 大）。
- **风险**：中。SVG 可内嵌脚本，需前端 review 是否关闭脚本执行能力。

### 方案 C：提供图片 URL 通道（http 外链）

- **操作**：平台若支持 code 节点将生成的图片上传至文件服务并返回 http 图片 URL，则由 URL 承载图片。
- **改动量**：大（需平台提供文件上传 API 或支持 code 节点产出图片附件）。
- **风险**：低。

### 方案 D：接入平台原生图表组件（mcp-server-chart / agent 插件）

- **操作**：用平台官方图表工具渲染图表。
- **现状**：此前 agent 节点的 ReAct 策略显示「未安装」，需先解决插件安装问题。
- **改动量**：最大（工作流重构 + 插件依赖）。

## 五、期望

请 IT 同学帮忙确认两件事：

1. 前端 markdown 渲染的 **CSP 是否拦截了 `data:` 图片源**？若是，能否按**方案 A** 放行 `data:image/png`（`img-src` 增加 `data:`）？
2. 平台是否提供**代码生成图片的官方展示通道**（如 http 图片 URL 或原生图表组件）？若有，请告知接入方式。

在任一方案落地前，智能体已降级为**纯 markdown 表格**承载图表信息（数字完整、无任何拦截风险），业务可正常使用。

## 附：当前图表的技术实现要点

- 图表由 code 节点内**纯 Python 标准库**生成（PNG 用 `zlib`+`struct`+`base64` 光栅化，零 matplotlib/PIL/numpy 依赖）。
- 所有图表数字**直接来自计算引擎**（单一真相源），不经 LLM 重算，精度可靠。
- PNG 单张约 2–3KB（base64），体积很小，适合内嵌。
