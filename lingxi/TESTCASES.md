# 测试用例集（平台验收用）

> 用法：在灵犀平台导入 `out/TCL门店盈利测算智能体.yml` 后，把每个用例的【输入】原样发给智能体，比对【期望输出】中的核心指标即可判定通过。
> 所有金额单位为元，输入可说「30万」=300000、「30%」=0.30（LLM 抽取环节自动换算）。
> 每个用例的【输入】都是**独立完整**的（含完整的固定费用），无需参照其他用例，可直接单独复制发送。

## 单一 yml（图表表格化兜底，零插件依赖）

- 当前 `out/` 下只有一个文件：**`TCL门店盈利测算智能体.yml`**。
- **图表承载最终定案（2026-09-07）：纯 markdown 表格**。平台前端对裸 `<svg>`（剥图形标签）与 `data:image/png`（返回 `[Image blocked]`）**均拦截**，改用不被任何渲染器拦截的表格承载图表信息，稳定可渲染。
- 图表信息 100% 无损承载在表格里：**阶梯边际贡献表**（= 瀑布图，每段贡献额+累计贡献额）＋**核心指标表**（含保本销售额、安全边际率）。
- 不依赖 `langgenius/agent` 插件、`mcp-server-chart`、`qwen3.6-plus`，也不依赖 matplotlib/PIL/numpy。数字 100% 由引擎算进表格，不经 LLM。
- `calc_engine.py` 里 PNG 生成函数（`charts_md`/`waterfall_png`/`cvp_png` 等）**保留未删**，等平台开放图片通道（白名单 data URI 或原生图表）可一行切回。

## 用例 8：多方案对比（阶段2）✅

**输入**

> 帮我对比两个方案。方案一提价策略：智屏 X30万毛利30%、C28万毛利22%、P24万毛利15%、S5万毛利11%，变动费用率11.5%。方案二扩量策略：智屏 X40万毛利30%、C35万毛利22%、P28万毛利15%、S6万毛利8%，变动费用率11.5%。固定费用都是场地1.7万展台0.8万人力1万日常0.2万运营0.4万

**期望输出**

| 方案     | 销售额 | 毛利额 | 利润  | 毛利率  | CMR    | 保本点  |
| -------- | ------ | ------ | ----- | ------- | ------ | ------- |
| 提价策略 | 87.00万 | 19.31万 | 5.21万 | 22.20% | 10.70% | 38.33万 |
| 扩量策略 | 109.00万 | 24.38万 | 7.75万 | 22.37% | 10.87% | 37.73万 |

**结论要点**：扩量策略全面占优——利润更高（7.75万 > 5.21万），且保本点更低（37.73万 < 38.33万，安全边际更大）。核心差异在销售额体量带来的利润规模（两方案 CMR 几乎相同），应优先推荐扩量策略。

> 说明：本用例的 S 系列**无总部补贴**（与用例 1 不同），故提价策略利润为 5.21 万。

## 用例 12：修改数据重算（多轮对话）✅

> 先发用例 1 的输入，得到结果后，**在同一个对话里要求修改某项数据重新计算**，验证能正确合并增量修改并重算。

**第一步输入**（同用例 1）
> 帮我测算智屏门店：X系列30万毛利30%，C系列28万毛利22%，P系列24万毛利15%，S系列5万毛利8%有总部补贴2万，变动费用率11.5%，固定费用场地1.7万展台0.8万人力1万日常0.2万运营0.4万

**第二步修改**
> 把 S 系列的毛利率改成 10%，重新算一下

**期望行为**
- 系统应重新输出一份完整测算，其中 **S 系列毛利率已改为 10%**，其余系列（X/C/P）维持上一轮的值不变（X30万毛利30%、C28万毛利22%、P24万毛利15%）。
- 门店利润/CMR/保本点应**随 S 毛利变化而变化**（S 毛利 8%→10% 会改善边际贡献，S 系列 CMR 从负值 0.08-0.115=-0.035 变为 0.10-0.115=-0.015，利润上升）。
- **不报错**，且不应把 X/C/P 数据丢失或清零。

**验收要点**：这一轮能通过，依赖两点同时成立——①抽取节点判为 `calc`（而非 chat）并按"增量合并"输出完整数据；②上一轮 answer 末尾的「本次测算输入数据」明细能被 LLM 记忆窗口读到。若结果里 X/C/P 数据丢失，说明记忆窗口或合并 prompt 未生效。

3. 固定费用应来自独立「门店信息」sheet（场地 2.5万+展台 1.2万+人力 1.8万+日常 0.3万+运营 0.5万 = 6.3万），而非品类 sheet 内。
4. ⚠️ **需平台实测**：文档提取器对 xlsx **多 sheet** 的处理——是全部 sheet 合并输出（已兼容）还是只读第一个 sheet（只拿到门店信息、解析不到品类）。若只读首 sheet，需改用 code 节点直接读 xlsx 二进制的备选方案。
5. 同模板有《顺加制》版本（`TCL_多品类_顺加制_示例.xlsx`，原始版同样 S 列残缺，如需验收顺加制请先比照本用例补全 S 列）。
